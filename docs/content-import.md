# 학습 콘텐츠 가져오기

Sprache는 PDF, Excel, CSV, JSON, JSONL 파일을 모든 지원 플랫폼에서 같은 규칙으로
검토한 뒤 로컬 단어장에 저장한다. 파일을 선택하는 것만으로는 저장되지 않으며,
사용자가 변경점을 확인하고 `반영`을 누른 경우에만 SQLite가 바뀐다.

## GitHub 언어팩 받기

`자료실 → 추가 → 언어팩 받기`는 공개 GitHub 카탈로그를 읽어 현재 학습 언어의
팩부터 보여 준다. 다른 언어 또는 전체 팩으로 필터를 바꿀 수 있고, 이미 설치한
팩은 `설치됨`, 같은 ID의 새 revision은 `업데이트`로 구분한다.

다운로드할 때 앱은 HTTPS·동일 호스트 상대 경로·20MB 제한·정확한 바이트 크기·
SHA-256·팩 메타데이터·안정 ID·언어·문장 토큰을 다시 검증한다. 검증된 항목에는
`source_id=language-pack:<pack-id>`와 버전·revision·출처·라이선스를 구조적으로
보존하고 언어별 기본 분배 키를 붙인다. 이후 단계는 일반 파일과 동일한
`기존 자료 비교 → 선택 → 원자적 반영 → 되돌리기` 흐름이다.

팩 원본 JSON은 로컬 백업이나 Drive에 복제하지 않는다. 반영된 학습 항목만 사용자
자료로 저장되어 기존 Google Drive snapshot 동기화 대상이 된다. 작성자는
`language-packs/templates/example-language-pack.json`을 복사해 `packs/`에 올리며,
카탈로그의 크기·SHA-256은 GitHub workflow가 자동 생성한다.

## PDF에서 단어 가져오기

PDF를 고르기 전에 학습 대상, 언어, 분배 키와 그룹을 먼저 정한다. 분석은 페이지
단위로 진행되며 취소할 수 있다. `단어 - 뜻`, `단어: 뜻`, 탭 또는 여러 칸으로
나뉜 2열 표처럼 뜻의 대응이 명확한 행만 기본 선택한다. 일반 문서에서 빈도와
문맥을 기준으로 찾은 후보는 뜻을 비워 두고, 사용자가 뜻을 입력한 항목만 저장한다.

검토 화면에서는 단어·뜻·문맥·페이지·빈도·중복 상태를 한꺼번에 확인하고 수정할
수 있다. 기존 ImportPreview, 중복 병합, 초안 복구, 원자적 커밋, 가져오기
되돌리기와 Drive 동기화 규칙을 그대로 사용한다.

- 지원 언어: `ko`, `en`, `ja`, `de`, `fr`, `es`, `zh-Hans`
- 제한: 20MB, 500페이지, 추출 본문 200만 자, 후보 5,000개
- 암호화 PDF: 비밀번호를 현재 분석 세션에서만 사용
- 스캔 PDF: 텍스트가 없으면 OCR 미지원 안내
- 보존 출처: 파일명·SHA-256·페이지·짧은 문맥
- 보존하지 않는 것: PDF 원본, 비밀번호, OAuth 토큰

## Excel 템플릿 선택

가져오기 화면은 두 Excel 파일을 제공한다.

| 템플릿 | 권장 대상 | 구성 |
| --- | --- | --- |
| 간편 템플릿 | 처음 등록하거나 일상적으로 단어·예문을 추가하는 사용자 | 필수 4열과 그룹·품사·추가 정답·예문·한국어 발음·문제 토큰·태그·레벨·우선순위·주제 ID·분배 키·고정 ID를 포함한 19열 |
| 전체 템플릿 | 여러 예문, 다국어 읽기, 출처·라이선스·버전·고정 ID를 관리하는 사용자 | 38개 전체 필드 |

간편 템플릿의 `작성 안내` 시트를 먼저 읽고 `간편 업로드` 시트의 예시 행을
삭제하거나 바꾼다. 처음에는 `language`, `type`, `term`, `meaning`만 채워도
된다. 같은 `language`·`type`·`term`·`part_of_speech`가 여러 행에 있으면
뜻·허용 정답·그룹을 합치며 기존 뜻을 지우지 않는다.

단어 행에서 `example`과 `example_translation`을 함께 입력하면 단어 카드의
대표 예문뿐 아니라 독립 문장 학습 항목도 생성한다. `example_tokens` 또는
`sentence_tokens`를 `|`로 나누면 문장 배열과 빈칸 문제에 사용할 수 있다.
`korean_pronunciation`에는 목표 표현을 한국어로 읽는 법을 적는다. 예문에는
`example_pronunciation`을 쓰며 전체 템플릿의 두 번째·세 번째 예문에는
`example_2_pronunciation`, `example_3_pronunciation`을 사용한다.
야구·아이돌·자격증처럼 언어가 아닌 공부는 앱에서 주제를 먼저 만든 뒤
`language=ko`와 해당 `subject_id`를 사용한다.

`한국어_발음`, `한글_발음`, `hangul`, `korean_reading`도
`korean_pronunciation`의 별칭으로 인식한다. 일반 `reading` 열은 영어·독일어·
프랑스어·스페인어에서 한국어 발음으로, 일본어에서 가나로, 중국어에서 병음으로
해석한다. 일본어와 중국어의 한국어 발음은 명확한
`korean_pronunciation` 열을 사용하는 편이 안전하다.

## 고정 ID와 콘텐츠 교정

`id`를 비우면 `subject_id`·언어·종류·정규화된 표현·첫 번째 뜻·품사를
조합해 UUID v5를 만든다. 개인 자료를 한 번 가져오는 데에는 편리하지만, 배포한
번들의 뜻이나 예문 문구를 고치면 파생값이 달라질 수 있다. 따라서 공유 템플릿과
번들 콘텐츠는 첫 배포 때 발급한 UUID를 `id`에 명시하고 다음 원칙을 적용한다.

- 같은 학습 개념의 정의·표현·예문을 더 정확하게 고칠 때는 최초 ID와 진도를
  유지하고 `content_version`만 올린다.
- 완전히 다른 개념으로 교체할 때는 기존 ID를 재사용하지 않고 새 ID를 발급한다.
  기존 항목과 진도는 자동 삭제하지 않으며 가져오기 검토 화면에서 새 항목으로
  확인한다.
- 품사는 중복 정체성에 포함된다. 같은 항목을 JSON·CSV·XLSX로 제공할 때
  `part_of_speech`까지 같아야 한다.
- ID가 없던 v1 번들은 당시 파생된 UUID를 v2의 명시적 ID로 승격했다. 따라서
  v1을 먼저 가져온 사용자도 v2를 다시 가져오면 같은 ID로 병합되어 단어 진도가
  이어진다. 반대로 v2 뒤에 v1을 다시 가져와도 같은 ID 중복으로 처리한다.
- 예문과 뜻의 쌍을 교정할 때는 `example_id`(추가 예문은
  `example_2_id` … `example_10_id`)에 최초 자동 생성 문장 ID를 고정한다.
  그러면 기존의 잘못된 예문 문장이 새 예문으로 병합·교정되고 중복 문장이
  남지 않는다. 독립 문장으로 관리할 자료는 `sentence` 행의 기존 `id`를 유지한다.

현재 여러 형식에 겹쳐 실리는 회귀 기준은 다음과 같다.

| 항목 | 주제 | 품사 | 고정 ID |
| --- | --- | --- | --- |
| WHIP | `general:baseball` | `other` | `f64d5def-2065-5768-aeb0-8374e6a201ed` |
| OPS | `general:baseball` | `other` | `1c6b1541-b797-56aa-8255-5767db996318` |
| 생얼 | `general:idol-fandom` | `noun` | `14eccebd-807a-5497-b745-89c8c89a2740` |

한국어 발음이 비어 있으면 기기 안에서 다음 순서로 보완한다. 사용자가 입력한
`korean_pronunciation`이 항상 우선하며, 영어·독일어·프랑스어·스페인어는
라틴 문자 원문, 일본어는 `romaji` → `kana` → 가나로만 된 원문, 중국어는
`pinyin`을 사용한다. 한자만 있는 일본어·중국어 원문은 임의로 읽지 않고 검토
화면에 비차단 안내를 표시한다. 이 경우에도 항목 저장과 기기 TTS 음성 재생은
가능하다.

## 분배 키와 Google Drive 데이터 병합

가져오기 화면의 `분배 키`는 업로드 파일을 어느 주제와 그룹으로 보낼지 기억하는
안정적인 사용자 키다. 예를 들어 `travel-core`를 `영어` 주제와 `여행 준비`
그룹에 연결하면 다음 파일에서도 같은 키를 입력하는 즉시 같은 목적지가 선택된다.
파일 안의 `distribution_key` 열도 같은 규칙으로 인식하며, 화면에서 지정한 키와
목적지가 파일 값보다 우선한다. 화면 키를 비워 두면 한 파일 안의 여러 키도
각각 저장된 주제·그룹·언어 규칙으로 분배한다. 아직 규칙이 없는 키는 해당 행의
`subject_id` 또는 현재 주제를 기준으로 최초 규칙을 만들며, 같은 키가 한 파일에서
서로 다른 `subject_id`를 가리키면 잘못 섞지 않고 수정 안내를 표시한다.

- 여섯 기본 키 `lang:en`, `lang:ja`, `lang:de`, `lang:fr`, `lang:es`,
  `lang:zh-hans`는 각각 해당 언어 주제로 자동 분배한다.
- 기본 키도 사용자가 목적지를 저장하면 저장 규칙이 기본값보다 우선한다.
- 사용자 키는 공백을 하이픈으로 정규화하며 최대 48자다. 한글·콜론·`@` 같은
  안전한 사용자 문자는 유지하고, 태그 구분과 충돌하는 쉼표·세미콜론·세로줄·
  슬래시·역슬래시와 제어 문자는 거부한다.
- 같은 키를 다시 저장하면 새 규칙을 만들지 않고 기존 목적지를 갱신한다.
- 분배 규칙은 학습 설정 snapshot에 포함되어 연결된 모든 기기로 동기화한다.
- `반영`은 파일 행을 검증된 학습 항목으로 정돈한 뒤 SQLite transaction에
  신규 추가 또는 기존 항목 갱신으로 저장한다. 동일 표현에 새 뜻만 있으면
  기존 항목과 진도를 유지하면서 뜻·허용 정답·읽기·그룹을 합친다.
- Google Drive가 연결된 경우 기존 snapshot을 먼저 내려받아 병합한 뒤 같은
  논리 데이터셋의 `content/custom-items.json`과 `state/settings.json`을
  갱신한다. 다른 Android·Windows 기기는 이 정돈된 결과와 분배 규칙을 읽는다.
- 두 기기가 오프라인에서 같은 주제의 같은 표현을 각각 보강했어도 뜻·허용
  정답·읽기·그룹을 합집합으로 수렴시키고, 중복 ID의 진도는 살아남은 항목 ID로
  옮긴다. 항목의 현재 분배 키는 최신 항목의 키 하나만 유지해 키 조회가
  모호해지지 않으며, 양쪽 학습 그룹은 모두 보존한다.
- 원본 Excel·CSV·JSON·JSONL 바이트는 Drive나 로컬 미러에 별도 복제하지 않는다.
  파일명과 SHA-256은 중복 가져오기 안내용 이력만 SQLite에 남긴다.
- Drive가 일시적으로 실패하면 정돈된 로컬 변경만 동기화 대기열에 유지한다.
  원본 파일을 두 번째 업로드 대상으로 만들지 않는다.
- 항목의 언어와 읽기 표기는 동기화하지만 설치된 TTS 음성의 이름은 동기화하지
  않는다. Android와 Windows는 항목 언어의 `ttsLocale`에 맞는 기기 내 음성을
  고르고, 같은 로케일에서는 오프라인 음성을 우선한다.

## Excel로 내보내고 다시 가져오기

`설정 → 데이터와 개인정보 → 로컬 백업 → 개인 콘텐츠 Excel`을 누르면 현재
사용자가 만든 단어와 문장을 `.xlsx`로 저장한다. Android와 Windows가 같은
28열 형식을 사용한다.

- 여러 뜻과 그룹은 각 셀에서 `|`로 구분한다.
- `korean_pronunciation`·`kana`·`romaji`·`pinyin`, 허용 정답, 예문과 번역,
  문장 배열 토큰을 보존한다.
- `source_id`·`source_url`·`author`·`attribution`과 콘텐츠 버전을 보존한다.
- 언어 코스와 일반 공부 주제를 구분하는 `subject_id`를 보존한다.
- 우선순위와 콘텐츠 버전은 Excel 숫자 셀로, 나머지 사용자 입력은 수식이 아닌
  안전한 문자열 셀로 기록한다.
- 내부 분배 키는 `distribution_key` 열로 보존하고 일반 태그 열과 분리한다.

내보낸 파일을 수정한 뒤 가져오기 화면에서 선택하면 바로 덮어쓰지 않는다.
신규·동일·변경·차단 행과 필드별 차이를 검토한 뒤 `반영`을 눌러야 SQLite가
바뀐다. 동일 표현에 뜻만 추가했다면 기존 뜻을 유지한 채 새 뜻을 병합할 수
있다. `CSV 호환본`은 다른 도구와의 교환용이며 같은 28열 데이터를 사용한다.

Excel/CSV 내보내기는 개인 학습 콘텐츠를 편집하기 위한 형식이다. 앱 설정,
진도, XP, 최근 세션까지 완전히 복원하려면 같은 카드의 검증된 JSON 백업을
사용한다.

## 안전 한도

| 항목 | 한도 | 초과 시 동작 |
| --- | ---: | --- |
| 파일 크기 | 20MB | 파일 전체 거부, 분할 안내 |
| 학습 데이터 행 | 20,000행 | 파일 전체 거부, 분할 안내 |
| 열 | 64열 | 사용하지 않는 열 삭제 안내 |
| 셀 또는 JSON 필드 | 20,000자 | 행·필드 위치를 표시하고 파일 전체 거부 |
| 단어와 자동 생성 예문 합계 | 50,000개 | 예문 축소 또는 파일 분할 안내 |

Excel 압축 파일은 위 한도 외에도 ZIP 항목 1,000개, 압축 해제 크기 100MB로
제한해 비정상 압축 파일로 인한 메모리 고갈을 막는다.

## 처리 순서

1. 선택한 파일의 크기와 형식을 확인한다.
2. 별도 실행 스레드에서 UTF-8 해석, 행·열·셀 한도, 콘텐츠 규칙을 검사한다.
3. SHA-256으로 이전에 같은 파일을 가져왔는지 확인한다.
4. 신규·변경·동일·차단 항목과 필드별 차이를 검토 화면에 표시한다.
5. 사용자가 신규 추가, 뜻·그룹 병합, 기존 값 유지 또는 교체를 선택한다.
6. 저장 직전 모든 선택 항목을 다시 검증한다.
7. 항목, 삭제 tombstone, 가져오기 이력을 하나의 SQLite transaction으로 저장한다.
8. 성공한 뒤에만 화면 상태를 바꾸고 Drive 동기화 큐에 넣는다.

6~7단계에서 앱 종료, 검증 실패 또는 저장 오류가 발생하면 일부 항목만 남기지
않는다. 기존 단어장과 가져오기 이력은 그대로이며 같은 검토 결과로 다시 시도할
수 있다.

## 파일을 나누는 예

20,000행을 넘는 `my-words.csv`는 헤더를 각 파일에 반복해서 넣는다.

```text
my-words-01.csv: 헤더 + 1~20,000행
my-words-02.csv: 헤더 + 20,001행 이후
```

안정적 ID와 의미상 중복 검사를 사용하므로 파일을 순서대로 가져와도 같은
표현·뜻·품사가 불필요하게 중복되지 않는다. 여러 뜻은 `meaning`에 `|`로
구분하고, 여러 그룹은 `group`에 `|` 또는 `,`로 구분한다.
