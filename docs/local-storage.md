# Google Drive 저장과 앱 내부 캐시

## 저장 원칙

- 사용자가 보관 위치를 따로 지정하지 않는다.
- 학습 자료, 진도, 설정, 세션 기록의 영구 보관 대상은 Google Drive 하나다.
- 앱 전용 Drift SQLite는 오프라인 작업과 안전한 동기화를 위한 내부 캐시다.
- SQLite 파일은 운영체제가 정한 앱 전용 데이터 디렉터리에 두며 사용자 문서 폴더나 공유 폴더에 만들지 않는다.
- Drive 장애 중 생긴 변경은 앱 내부 대기열에 남기고, 연결이 복구되면 같은 Drive 저장본에 반영한다.

## Google Drive 경로

사용자가 Google Drive Picker에서 고른 폴더 아래에 앱 전용 루트를 준비한다.

```text
선택한 Drive 폴더/
└─ Sprache/
   ├─ manifest.json
   ├─ content/
   ├─ state/
   ├─ backups/
   └─ quarantine/
```

앱은 표시 경로가 아니라 Google Drive 파일 ID로 폴더와 파일을 참조한다. 폴더를 옮기거나 이름을 바꿔도 ID가 유효하면 같은 저장본을 사용한다. `manifest.json`이 가리키는 파일의 길이와 SHA-256을 확인한 뒤에만 로컬 캐시와 병합한다.

이전 버전의 `WordStudyData/`가 이미 있으면 새 폴더를 중복 생성하지 않고 기존 폴더 ID를 그대로 재사용한다.

## PDF와 가져오기 파일

- PDF, Excel, CSV, JSON, JSONL 원본은 선택한 기기의 메모리에서만 읽는다.
- 원본 파일을 앱 데이터 폴더나 Google Drive에 복사하지 않는다.
- PDF는 분석이 끝나면 원본 바이트 참조를 해제한다.
- 사용자가 검토하고 선택한 단어·뜻·페이지 번호·짧은 문맥·원본 SHA-256만 학습 데이터에 포함한다.
- 가져오기 결과를 앱 내부 트랜잭션에 반영한 직후 Google Drive 동기화를 요청한다.
- Drive에 바로 쓰지 못한 변경은 원본 파일이 아니라 정돈된 학습 snapshot만 재시도한다.

## 이전 로컬 폴더 기능 정리

이전 버전에서 사용자가 지정한 로컬 보관 폴더는 더 이상 활성 저장 대상으로 사용하지 않는다. 앱 시작 시 다음 항목을 정리한다.

- 저장된 로컬 폴더 경로와 마지막 백업 메타데이터 삭제
- Android 문서 트리의 지속 접근 권한 반환 시도
- 이전 가져오기 임시 파일 삭제

사용자가 만든 기존 백업 파일 자체는 자동 삭제하지 않는다. 데이터 손실을 피하기 위해 파일 삭제는 사용자가 해당 폴더에서 직접 결정한다.

## 예외

- OAuth 토큰은 플랫폼 보안 저장소에만 둔다.
- 알림, 창 크기, 기기별 접근성처럼 동기화 대상이 아닌 값은 앱 전용 설정에 둔다.
- 사용자가 직접 요청한 내보내기 파일은 사용자가 선택한 위치에 한 번 저장할 수 있지만 자동 저장 경로로 사용하지 않는다.
