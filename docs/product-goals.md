# Sprache 지속 개발 목표

기준 명세: `codex_wordstudy_app_spec.txt`  
최종 제품 방향: 한국어 사용자가 Android와 Windows에서 같은 Google Drive 학습 저장소를 사용하며 여섯 언어를 오프라인 우선으로 학습하는 앱

## 제품 불변 조건

- 영어·일본어·독일어·프랑스어·스페인어·중국어 간체를 BCP 47 태그로 분리한다.
- 학습 콘텐츠와 상세 진도의 원본은 사용자 Drive와 로컬 SQLite이며 Railway에는 계정-폴더 연결만 저장한다.
- 네트워크·인증·원격 데이터가 실패해도 로컬 학습은 계속 가능해야 한다.
- 손상되거나 앱보다 최신인 원격 데이터는 정상 로컬 데이터를 덮어쓰지 않는다.
- 단어·문장·읽기·문장 토큰은 저장 직전 같은 검증 규칙을 통과해야 한다.
- Android는 짧고 반복적인 학습 흐름, Windows는 크기 조절 가능한 업무 도구형 흐름을 유지한다.

## 현재 달성 기준

- 여섯 언어 내장 콘텐츠 600개와 카드·퀴즈·문장·듣기·발음·미션 학습
- SQLite 진도·사용자 콘텐츠·설정·세션 저장
- Drive snapshot 기반 진도·설정·활성 세션·사용자 콘텐츠 동기화
- SQLite 영속 업로드 큐, 재시작 복원, 백오프와 설정 화면 재시도 상태
- Drive manifest file ID·revision·SHA-256 검증과 pull 이후 변경 충돌 방지
- 활성 세션 및 사용자 콘텐츠 삭제 tombstone
- CSV·JSON·JSONL 행 단위 검증, 의미상 중복 판정과 충돌 정책
- 품사·출처·라이선스·원본 버전·콘텐츠 버전의 SQLite·Drive 보존
- 덱·태그·레벨·학습 단계·단어/문장 비율 기반 세션 빌더와 Drive 설정 동기화
- 진행 중 세션의 일시정지·재개·재시작·오답/남은 문제 분기와 계보 동기화
- Android APK와 Windows x64 실행 패키지

## 계속 추구할 고도화 목표

### 1. 연결 신뢰성

- 완료: snapshot 다운로드에 manifest 파일 ID·revision·SHA-256 검증 적용
- 완료: pull 지문 기반 optimistic concurrency와 업로드 충돌 재조회
- 완료: pending sync SQLite 큐와 재시도 상태 표시
- 남음: 콘텐츠와 상태를 여러 파일로 분리한 manifest 기반 증분 동기화
- 인증 만료·권한 철회·폴더 삭제·API 제한을 구분한 복구 화면

### 2. 콘텐츠 정합성

- 완료: 사용자 콘텐츠에 품사·출처·라이선스·원본 버전·콘텐츠 버전 추가
- 완료: 내장 콘텐츠 600개의 품사·출처 메타데이터와 출처 등록 문서 적용
- 완료: ID와 무관한 의미상 중복 판정 및 기존 학습 기록 ID를 보존하는 교체
- 완료: 가져오기 전에 필드별 변경 비교와 중복 후보를 나란히 표시
- 일본어 가나/로마자와 중국어 병음의 형식 품질 검사
- 내장 콘텐츠 번역의 언어별 원어민 검수와 체크리스트 이력화

### 3. 학습 유연성

- 완료: 덱·태그·레벨·기억 단계·단어/문장 비율을 조합하는 세션 빌더
- 완료: Android·Windows 공통 세션 미리보기·저장·학습 시작과 최신 설정 우선 동기화
- 완료: 진행 중 세션 일시정지·재개·오답/남은 문제 분기·재시작 기록과 Drive 동기화
- 코스별 일일 목표와 계정 공통 XP의 구분 표시
- 키보드만으로 가능한 Windows 문제 풀이와 검색

### 4. 안정성과 복구

- 손상 원격 파일의 격리 사본과 복구 전 미리보기
- 로컬 DB 마이그레이션 실패 시 읽기 전용 복구 모드
- 대용량 가져오기·동기화의 트랜잭션 및 중단 복구 테스트
- 실제 Android·Windows 두 기기 장시간 오프라인 충돌 시험

## 다음 우선순위

1. 콘텐츠와 상태 파일을 분리한 manifest 증분 동기화
2. 인증·권한·폴더·API 제한별 복구 화면과 원격 파일 격리
3. 일본어 가나/로마자와 중국어 병음의 형식 품질 검사
4. 코스별 일일 목표와 계정 공통 XP의 구분 표시
5. 실제 Google OAuth 자격 증명으로 Android·Windows 두 기기 운영 검증

각 묶음은 정적 분석, 단위·통합·위젯 테스트, 가능한 플랫폼 빌드와 배포 파일 검증을 통과해야 완료로 기록한다.
