- 로컬 변경마다 최신 전체 snapshot을 SQLite `pending_syncs` 한 건으로 합쳐 저장

- Drive manifest의 파일 ID로 snapshot을 읽고 metadata revision과 원본 바이트 SHA-256 검증
- HTTP 장애를 손상 JSON으로 오인하지 않고 권한·네트워크 경로로 전달
- pull 이후 manifest 지문이 바뀐 경쟁 조건을 업로드 전에 거부하는 통합 테스트
- 설정 화면에서 업로드 대기·재시도 횟수·다음 시각과 재시작 후 Google 재연결 동작 제공

## 실서비스 전 남은 외부 작업

코드와 설정 경로는 구현했지만 다음 작업은 소유자 계정과 비밀값이 필요해 로컬 Mock 검증 범위에 포함하지 않았다.

1. Google Cloud 프로젝트에서 Android·Desktop OAuth 클라이언트와 Drive Picker API를 설정한다.
2. 실제 Android release 인증서 SHA-1/SHA-256을 OAuth 클라이언트에 등록한다.
3. Railway 프로젝트에 PostgreSQL과 환경 변수를 등록하고 API를 배포한다.
4. 실제 두 기기에서 같은 Drive 폴더를 선택해 동기화 충돌·복구를 확인한다.
5. GitHub에 푸시한 뒤 Actions의 세 잡을 원격 실행한다.
6. 실제 Android 기기에서 여섯 언어의 음성 인식 언어팩과 마이크 채점을 확인한다.

구체적인 절차는 `docs/google-setup.md`, `docs/railway-deploy.md`, `docs/build-and-release.md`에 있다. 소유자에게 받을 공개 설정값과 비밀 변수의 등록 상태는 `docs/integration-inputs.md`에서 관리한다.

## 유지보수 경고

현재 Flutter 3.44.8에서는 빌드가 통과하지만 `file_picker`, `flutter_tts`, `speech_to_text`가 Kotlin Gradle Plugin을 직접 적용한다는 향후 호환성 경고가 발생한다. Flutter를 다음 주요 버전으로 올리기 전에 세 플러그인의 Built-in Kotlin 지원 버전을 확인해야 한다.

Windows의 `speech_to_text` 지원은 현재 베타이며 플러그인 언어 목록이 영어 중심이다. 따라서 Windows 영어 코스에서는 마이크 인식을 사용하고, 비영어 코스에서는 목표 발음 듣기와 수동 따라 읽기 완료 흐름으로 전환한다. Android의 실제 인식 가능 언어는 기기에 설치된 음성 인식 서비스와 언어팩에 따라 달라지며, 이번 헤드리스 빌드 환경에서는 실기기 마이크 품질까지 검증하지 않았다.
