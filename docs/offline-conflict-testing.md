# 장기 오프라인 충돌 검증

## 목적

Android와 Windows가 같은 Drive 저장소에서 갈라진 뒤 장기간 오프라인으로
사용되더라도, 어느 기기가 먼저 다시 연결되는지와 관계없이 같은 결과에
수렴하고 한쪽 작업이 조용히 사라지지 않아야 한다.

## 자동 시뮬레이션

`test/sync/offline_conflict_stress_test.dart`는 서로 다른 영구 `replicaId`를
가진 Windows·Android 저장소가 45일 동안 독립적으로 학습한 상황을 만든다.

시뮬레이션에는 다음 변경이 함께 들어간다.

- 각 기기에서만 만든 단어와 서로 다른 항목의 진도
- 같은 항목을 서로 다른 시각에 학습한 충돌
- 한 기기의 항목 수정과 다른 기기의 삭제 tombstone
- 즐겨찾기, 미션 완료, 사용자 주제, 저장한 학습 일정
- 한 기기의 즐겨찾기 해제·학습 제외 취소와 저장 일정 삭제
- 완료 세션과 오답 기록
- 진행 중 세션 생성과 더 늦은 세션 삭제
- 같은 주제의 일일 목표 변경
- 양쪽에서 따로 얻은 계정 XP와 같은 날짜·코스의 오늘 XP
- 첫 업로드 중단과 SQLite 대기 작업 재시도

각 시나리오는 Windows 우선 연결과 Android 우선 연결을 모두 실행하고,
반복 동기화 뒤 cloud·Windows·Android snapshot의 시각 필드를 제외한
내용이 동일한지 확인한다.

## 결정 규칙

- 계정 XP는 기기별 증가 전용 카운터로 저장한다. 같은 기기 카운터는 큰 값을
  선택하고 서로 다른 기기 카운터는 합산하므로 동시 학습 XP가 사라지지 않는다.
- 기기 ID가 없던 구버전의 `totalXp`는 `legacy` 카운터로 승계한다.
- 오늘 XP도 날짜·코스·기기별 증가 전용 카운터로 병합한다. 과거 시각의 학습
  기록은 총 XP와 항목 진도에는 반영하되 현재의 오늘 XP·연속일·마지막 학습일을
  과거로 되돌리지 않는다.
- 활성 주제와 주제별 일일 목표는 변경 시각이 최신인 값을 선택한다.
  시각이 같거나 없는 구형 데이터는 고정된 tie-breaker를 사용한다.
- 즐겨찾기와 학습 제외는 설정 여부와 변경 시각을 함께 저장하고, 저장 일정
  삭제는 tombstone을 남겨 오래된 기기에서 다시 생기지 않게 한다.
- 진도는 항목별 `lastStudiedAt`, 사용자 콘텐츠는 `updatedAt`과 tombstone,
  완료 세션은 `endedAt`을 기준으로 결정적으로 병합한다.
- 원격 데이터가 한도를 넘거나 형식이 잘못되면 로컬 저장 전에 snapshot 전체를
  거부한다. XP 기기 원장은 최대 500개 기기까지 허용한다.

## 실기기 완료 조건

자동 시뮬레이션은 네트워크 순서와 병합 알고리즘을 검증하지만 OS 종료,
모바일 백그라운드 제한, 실제 Drive 전파 지연까지 대신하지는 않는다.
최종 실기기 검증은 다음 순서로 수행한다.

1. 동일한 운영 빌드를 Android 물리 기기와 Windows에 설치한다.
2. 같은 Drive 폴더를 연결하고 기준 snapshot을 한 번 동기화한다.
3. 두 기기를 네트워크에서 분리해 각각 다른 자료와 학습 기록을 만든다.
4. Windows 우선, Android 우선 순서를 각각 별도 데이터셋으로 재현한다.
5. 업로드 도중 네트워크를 끊고 앱 재시작 뒤 대기 작업이 재개되는지 확인한다.
6. 두 기기의 계정/오늘 XP·진도·자료·그룹·일정·완료 세션과 삭제 항목을 비교한다.
7. Drive manifest와 여섯 섹션 파일의 SHA·revision 검증 기록을 보관한다.

실제 Google 계정과 두 기기가 필요한 1~7은 운영 자격 증명 준비 후 수행하며,
완료 전에는 “실기기 검증 완료”로 기록하지 않는다.
