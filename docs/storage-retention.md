# 저장 공간 보존과 사용자 정리

Sprache는 앱 전용 데이터베이스 복구 사본과 Google Drive의 이전 동기화 섹션을
자동으로 삭제하지 않는다. 설정의 `저장 공간 관리`에서 현재 상태를 조회한 뒤,
30일 이상 지난 안전 후보만 사용자가 직접 선택할 수 있다.

사용자 지정 로컬 `Sprache` 미러는 별도 정책을 사용한다. 새 자동 저장이
성공하면 현재 `manifest.json`과 `manifest.previous.json`이 참조하는 두
generation을 보호하고 그보다 오래된 자동 generation만 best effort로
정리한다.

## DB 복구 사본·Drive 공통 원칙

- 기본 최소 보존 기간은 30일이다.
- 앱 시작, 로그인, 동기화, 업데이트만으로 삭제가 실행되지 않는다.
- 조회 당시와 삭제 직전의 상태가 다르면 전체 정리를 중단하고 새로고침을 요구한다.
- 현재 학습 데이터가 참조하는 파일은 나이와 관계없이 정리 후보가 아니다.
- 선택하지 않은 항목과 30일이 지나지 않은 항목은 변경하지 않는다.

## 로컬 DB 복구 사본

대상은 앱 문서 폴더의 `sprache-recovery/<UTC>-<reason>` 바로 아래 폴더다.

1. 각 사본의 최신 파일 수정 시각, 전체 바이트 수, 파일 수를 조회한다.
2. 최신 수정 시각이 현재 시각보다 30일 이상 오래된 사본만 선택 가능하게 한다.
3. 사용자가 `선택 영구 삭제`를 누르면 삭제 대상 수와 복구 불가능성을 다시 알린다.
4. 확인 후 현재 목록을 다시 읽어 수정 시각과 크기가 조회 당시와 같은지 검사한다.
5. 루트의 직접 자식이 아니거나 상태가 달라진 대상이 하나라도 있으면 삭제하지 않는다.

로컬 정리는 운영체제 휴지통을 거치지 않는 영구 삭제다. 그래서 Drive 정리보다
강한 확인 문구를 사용하고, 앱은 대상 폴더를 자동 선택하지 않는다.

## 사용자 지정 로컬 미러

Windows 파일시스템 또는 Android SAF로 선택한 `Sprache` 폴더에는 현재·이전
manifest, 그 manifest가 참조하는 `state/`·`content/` generation, 전체 복원
archive가 있다.

- 새 generation 파일의 길이·SHA-256을 검증하고 manifest 교체까지 성공한 뒤에만
  미참조 generation 정리를 시도한다.
- `manifest.json`과 `manifest.previous.json` 중 하나라도 해석할 수 없으면
  알 수 없는 generation을 자동 정리하지 않는다.
- 최신 archive를 읽을 때는 현재 manifest를 우선하고, 검증 실패 시 이전
  manifest가 참조하는 archive를 fallback으로 시도한다.
- 앱에서 로컬 폴더 연결을 해제하거나 다른 폴더로 바꿔도 기존 폴더와 파일은
  삭제하지 않는다. Android에서는 앱이 보유한 이전 문서 트리 권한만 반환한다.
- 실제 파일을 없애려면 사용자가 운영체제 파일 관리자에서 해당 `Sprache`
  폴더를 직접 확인하고 삭제한다.

로컬 미러의 JSON은 별도 암호화 파일이 아니다. 공유 폴더를
선택하면 다른 사용자나 동기화 서비스가 학습 내용을 볼 수 있으므로 개인 접근
권한이 있는 위치를 사용한다.

## Google Drive 이전 섹션

Drive 정리는 선택한 Sprache 폴더의 `state/`와 `content/` 안 JSON 파일만
조회한다.

1. 현재 `manifest.json`을 검증하고 manifest fingerprint를 만든다.
2. manifest가 파일 ID로 참조하는 현재 섹션은 목록에서 제외한다.
3. 참조되지 않고 수정 후 30일 이상 지난 JSON만 선택 가능하게 한다.
4. 사용자가 확인하면 manifest를 다시 내려받아 검증한다.
5. fingerprint가 바뀌었거나 선택한 파일이 새 manifest에서 참조되면 작업을 중단한다.
6. 안전 조건을 통과한 파일은 영구 삭제하지 않고 Google Drive 휴지통으로 이동한다.

Drive 목록 조회는 페이지를 모두 순회한다. 파일 크기 정보가 없더라도 안전 판정은
ID·참조 여부·수정 시각으로 수행하며, 표시 용량은 알려진 크기만 합산한다.

## 실패 처리

- 네트워크, 권한, manifest 검증 실패: Drive 항목을 이동하지 않고 오류를 표시한다.
- manifest 경쟁 변경: 사용자가 새로고침한 뒤 다시 선택해야 한다.
- 로컬 파일 변경: 어떤 폴더도 추가로 삭제하지 않고 새로고침을 요구한다.
- 로컬 미러 manifest 또는 참조 파일 손상: 현재 SQLite를 유지하고 정상
  current/previous archive만 복원 후보로 인정한다.
- 부분 Drive 실패: 이미 휴지통으로 이동한 수를 숨기지 않으며, 다음 조회에서
  현재 상태를 다시 계산한다.

## 검증 항목

- 현재 manifest 참조 파일은 후보 목록에 나타나지 않는다.
- 오래된 미참조 파일만 선택 가능하고 최근 파일은 비활성화된다.
- manifest가 조회 후 바뀌면 Drive PATCH 요청을 보내지 않는다.
- 로컬 사본의 크기나 수정 시각이 바뀌면 오래된 인벤토리로 삭제하지 않는다.
- 로컬 미러 정리는 current/previous manifest 참조를 보존한다.
- 로컬 폴더 연결 해제는 폴더의 파일을 삭제하지 않는다.
- 모바일 크기에서도 선택, 확인, 결과 안내가 잘리지 않는다.
- 정리 기능을 사용하지 않아도 기존 복구·동기화 동작은 그대로 유지된다.
